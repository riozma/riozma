This week, Procore and EarthCam both put "AI agents" into construction software, and a survey found that 43% of builders worry about liability for AI errors. To judge either, it helps to know what is actually inside these systems. The core idea is surprisingly simple.

One trick: predict the next word

A large language model (LLM), the engine behind ChatGPT, Claude or Gemini, does one thing: given a piece of text, it estimates how likely each possible next piece of text is, picks one, appends it and repeats. Those pieces are called tokens: whole words, parts of words or symbols. A model writes a three-page report by doing this a few thousand times in a row.

To get good at it, the model was trained on an enormous amount of text: books, websites, code, papers. During training it guessed the next token billions of times and adjusted its internal numbers (the parameters, today hundreds of billions) whenever it was wrong. Nobody programmed rules like "C30/37 is a concrete class". The model picked up such patterns because predicting text well requires them. Try it:

Why it is useful, and why it is wrong sometimes

Because so much expert writing is in the training data, the patterns the model learned include a lot of real knowledge, reasoning steps and writing style. That is why it can summarise a standard, draft a specification text or explain a failure mechanism. But the model optimises for plausible text, not for true text. When it lacks the fact, it does not say "I don't know" by default; it produces the most plausible-looking answer, as the third prompt above shows. This is called a hallucination, and it is the reason BRG found that liability for AI errors is builders' top risk concern.

From chatbot to agent

Two additions turn a text predictor into the "digital co-worker" Procore talks about:

First, the context window: everything the model sees when it answers, including attached documents. If you give it the right drawings or the right SIA chapter, it predicts from those instead of from memory, and errors drop sharply. Second, tools: the model can output a structured request ("look up submittal 14") that software executes, and the result is fed back into the context. The Model Context Protocol (MCP), used by both Procore and EarthCam this week, is a common plug for exactly that. An agent is simply this loop running several times.

What it means for us as future planners

The practical rule follows from the mechanism: an LLM is as reliable as the context you give it and the checks you put after it. The valuable skill is not prompting tricks but knowing which sources the model must read, which outputs need a calculation or a second look, and who signs off.
