Last week's focus was IFC, the open format for building models. But a project exchanges far more than models: lists of problems, the city around the plot, scans of what is already there. Each of these has its own open format, and knowing which one fits saves a lot of conversion pain. This week Stoa, a Helsinki start-up, raised money for an AI that reads drawings, schedules and models together; tools like that only work if the data underneath is in formats a machine can open.

Four layers of project data

It helps to think of four layers. IFC describes the designed building. Next to it sit the issues people raise about the design, the existing reality captured by scanners, and the city and terrain the building sits in. Each layer has an open standard:

BCF: the issue, not the model

The BIM Collaboration Format, also maintained by buildingSMART, carries comments about a model. A BCF "topic" holds a title, a status, who it is assigned to, comments, a screenshot and a saved camera view. Most importantly it lists the IDs of the elements concerned. When an engineer opens the topic in a different program, that program zooms to the same spot and highlights the same beam, because both programs read the same IFC IDs.

BCF exists as a file (a zipped .bcfzip with small XML files) and as a web interface, the BCF API, through which platforms exchange issues directly. It is what clash detection and model checking tools export, and it is the reason a clash found in Solibri can show up in Revit or Archicad. The catch: if a model is re-exported and the element IDs change, the old issues point at nothing.

CityGML and 3D Tiles: the building in its context

CityGML is a standard of the Open Geospatial Consortium (OGC) for 3D city models. It describes buildings, roads, vegetation and terrain at different levels of detail, from a simple block to a building with detailed roof shapes. City and national mapping agencies use it, and in Switzerland swisstopo offers a 3D model of all buildings, swissBUILDINGS3D, as open data. Planners use such models for shadow studies, views, noise and the first volume study in a competition.

Where CityGML is about meaning (this is a roof, this is a wall), 3D Tiles, also an OGC community standard and developed by Cesium, is about streaming: it cuts huge 3D datasets into tiles so that a browser can show a whole city or a scanned site smoothly. That is the platform Bentley bought, which featured in issue #5.

Point clouds: measured, but not yet understood

Laser scanners and photogrammetry produce point clouds: millions of points with coordinates and often colour. E57 (an ASTM standard) is the common open exchange format for scanner data; LAS and its compressed form LAZ come from airborne laser scanning and are used, for example, for swisstopo's national surface model swissSURFACE3D. A point cloud is precise but "dumb": it has no walls or pipes, only points. Turning it into a model ("scan to BIM") is still a lot of manual work, which is why so many start-ups try to automate it.

What it means for us as future planners

The formats only work together through shared references: element IDs that stay stable between exports, and coordinates that put the building in the right place in the city model and on the point cloud. Getting those two things right is unglamorous, but it decides whether a clash list, a scan and a city model can be combined, by people or by an AI. When you join a project, ask early which formats are agreed and who keeps the IDs stable.
